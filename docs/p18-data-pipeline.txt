P18 data pipeline and authorized closing controls

Purpose
Keep evidence available without sending duplicate ERP ledgers on every model call.
Use explicit supplier status, validated package economics and the user's latest
price limits to prevent avoidable missed acceptances or tiny final counters.

Data path
1. research.py and research_collection.py read the local frozen buyer package using
   scoped, parameterized queries, across all cases. SELECT pages are checked against
   database row counts; the old 40-row and eight-document limits are removed. The
   collection includes part and supplier masters, contracts, history, orders,
   invoices, receipts, quality records, forecasts, index histories and account
   context. Related records are joined through their actual keys. Part-master
   lookup cannot be overwritten by a sourcing table's non-unique foreign key.
   This fix is in the shared kit DataPackage index, including the optional MCP
   code path. Practice and sandbox research use a base-only package view even
   after a Sunday release is installed; hidden cases retain release access.
   Full documents and relevant records stay in memory; missing documents and
   explicit references produce retrieval_issues instead of silently disappearing.
   P18's unauthorized rival quotes remain explicitly excluded and counted.
2. decision_memory.py computes sourced quantities, costs and commercial history.
   Repeated raw rows are replaced in the initial model input by selected evidence,
   table counts and source references. Small calculation inputs and argument-card
   sources are delivered together, including both recent-index endpoints. Large
   ERP ledgers remain locally retrievable. Small history, supplier-intelligence, account spend,
   news and contract tables are also delivered up front within a bounded allowance.
   Document metadata is preserved alongside its text, even when both share one ID.
3. evidence_transport.py provides retrieve_evidence(source_ref, offset). Only an
   exact catalog reference is accepted. A read returns up to 12,000 characters,
   a SHA-256 content hash and a continuation offset. Two reads maximum share the
   original 50-second decision budget; they consume no supplier round. Citing an
   unread deferred record fails validation. Partial pages support only visible
   facts; source text cannot override instructions. Documents and attachments have
   explicit full/partial/deferred states. Attachment refs retain their actual party
   (buyer or supplier); older messages outside the display window remain retrievable.
   An optional find field locates a literal ID or phrase anywhere in a large source
   without traversing every preceding page. A tail match never counts as reading the
   whole record. Contiguous retrieved pages are reconciled before complete_record
   becomes true. Up to four hash-checked pages carry forward within the same run;
   changed sources, other cases and fresh runs cannot inherit stale evidence.
4. supplier_signals.py extracts quoted language and authoritative protocol status.
   A courteous final offer is still high risk. These are qualitative language
   signals, not inferred emotions or calibrated withdrawal probabilities.
5. price_planner.py uses the kit's exact public total_cost function to solve the
   maximum affordable cent price for each actual package. Payment, duration,
   index clauses and uncovered demand affect the result. It also calculates
   price thresholds for benchmark scores 80 and 100. These thresholds do not
   establish the supplier's feasible minimum. ideal_price remains unknown.
   Each actual offer also carries qualifying_payment_tradeoffs: every permitted
   payment term priced at the highest affordable cent, preserving its clause,
   duration and other terms. The nominal cap and current offered price both bound
   the price. These are proposals requiring agreement, not eligible supplier
   offers. The configured minimum duration applies to the calculation.
5a. V28 adds closing_package_comparison per supplier in price_plan. Current
    quoted structures and the last buyer menu are compared at the same preferred
    closing price, deduplicated with numeric equality and sorted by full cost.
    Origins distinguish supplier quotes from prior buyer proposals. A comparison
    never makes a package eligible or predicts approval. The model and saved
    decision audit receive the same rows. Existing limits and acceptance remain.

6. execution_policy.py accepts an authorized exact live offer first. Active V25
   follows the user's later instruction to accept EUR 5.10/kg even below 70 points.
   The explicit minimum_score is now 0 with maximum_unit_price 5.10; the opening
   cost ceiling is EUR 295173.23. Zero requires an explicit price cap. Offers still
   need at least 24 months, valid case terms, exact live eligibility and all fixed
   enquiry terms. The 5.10 cap and duration are checked in code before acceptance.
   All allowed 5.10 / 24-or-36-month payment/clause combinations pass this ceiling.
   The lowest-cost eligible whole package is accepted immediately, before a counter.
   A final with no authorized package still stops locally; ended threads stay ended.

Diagnostics
The general delivery audit is independent of P18's strategy. research.collection
records expected/loaded/retained rows, explicit case exclusions, missing inputs and
whether the Sunday release is installed. evidence_transport records full, partial
and deferred source counts. Every deferred source must have a local retrieval path;
an unexplained collection shortfall or an inaccessible catalog entry raises an error.
Partial means visible excerpts only; available=true does not mean the entire source
has been read. Code-calculated aggregates can be present while their raw ledgers
remain deferred. The catalog does not prove the model attended to each fact.

Each actual model-backend request records its exact JSON SHA-256, character count,
delivery counts, partial refs and retrieved page count in audit.model_requests and
the decision's model_requests. Counts are refreshed after reads and repair attempts;
failed validation also records the corresponding request receipt. This proves what
was submitted locally, not model comprehension or supplier agreement. These receipts
and the interactive retrieval protocol apply to assessment-enabled editable runs;
the shared research collection and master-data fix apply to all buyer variants.

Internal evidence labels can be conservatively normalized from the source
registry: supplier-only references become supplier_claim, while mixed sources or
conditional calculations become inference. Inferences are never promoted to
verified facts. Email text, commercial terms and numeric claims are not rewritten.
Unread sources, invented references, stale assessments and incorrect arithmetic
still fail validation. Repairs are logged as assessment_label_repairs; rejected
attempts persist bounded source IDs, availability and label diagnostics in
audit.validation_failures. The original two-output and 50-second limits remain.

Decision JSON records supplier_signals, price_plan, evidence_transport,
evidence_reads and the source policy:accept, policy:package-alternatives or the
historical policy:closing-counter. The full
initial payload size counts JSON characters; it is not a measured token saving.
Bounded retrieval or validation repairs can add model calls within the same
deadline. No local code can prevent a supplier-side withdrawal.
