P18 V22 implementation — 25 October 2026

Use
1. Select/paste prompts/p18-diagnostic-v22.txt in the workbench prompt field.
2. Start a fresh P18 evaluation using the model settings you want to keep constant.
3. Check the first decision source: policy:package-sequence:opening. It must
   propose EUR 4.60 / 60 days / 36 months / AS-14404 / 45% / 5% / 2026-08.
   Normal subsequent sources are policy:package-sequence:ppi_counter and
   policy:package-sequence:alloy_close. A qualifying exact offer takes precedence.

config/p18-consistent-package.json replaces the P18 entry in the local runtime
policy file. Other cases retain their existing entries. The old menu and 45-day
compromise are absent. See activation.json for the actual server reload time,
PID and policy snapshot. An already-running evaluation retains its old snapshot;
do not treat such a run as a V22 test. No browser prompt selection was changed.

Implementation
package_sequence.py derives progression from complete packages actually sent,
including after reconstruction or rewording. Each proposal retains payment,
duration and clause. Explicit/ambiguous structural refusal cues, off-sequence
history, exhausted stages and unavailable sends defer automatic progression.
The model receives package_sequence_state with the reason and relevant quote.
This is conservative text matching, not a complete semantic restriction parser.

execution_evidence.py inserts the appropriate checked argument:
opening: exact four PO records, correct part/supplier/date/price unit/price;
counter: exact delivered PPI endpoints and matching registered calculation;
close: exact delivered AS endpoints and matching registered calculation.
Duplicate or invalid/missing evidence is not claimed. For this sequence such
a failure defers the scripted move to the normal model/retrieval path with an
execution_control_deferral record. No automatic argument-free substitute is sent.

execution_policy.py retains exact qualifying acceptance before all counters.
PromptLabAgent checks proposals against live full cost, cap, duration and public
term options. The old policies remain usable in their own configurations, but
cannot be combined with consistent_package_sequence. Final offers with no
qualifying quoted package retain the local stop. A qualifying nonstanding
alternative remains available for unchanged binding confirmation. Existing
practice cleanup may separately close an abandoned session via its cleanup API.

supplier_signals.py distinguishes explicit confirmation of authority from a
requirement for approval. It no longer labels any occurrence of "authorized"
as an approval blocker. These remain fallible language cues, not proof of legal
authority or a universal semantic classification.
